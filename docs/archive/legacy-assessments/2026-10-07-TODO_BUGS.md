## 🔴 CRITICAL — Fix ASAP

- [ ] **BUG-1: `PERMISSION_DENIED` sa `truck_companies` Firestore collection**
  - Logcat: `E/TruckCompanyRepo: PERMISSION_DENIED: Missing or insufficient permissions. Cached 0 truck companies`
  - Fix: Update Firestore security rules para ma-read ng authenticated drivers ang `truck_companies`, OR mag-fetch via backend API
  - Files: Firestore console rules + `SecurityGuardRepository.kt`
  - Estimated effort: ~10 min

- [ ] **BUG-2: `scanToken()` Firestore fallback always returns `queuePosition = 1`**
  - Kapag sleeping ang Railway backend, drivers makikita "Position: 1" kahit hindi sila una sa pila
  - Fix: After writing to Firestore queue, query the collection to compute actual position
  - File: `app/src/main/java/com/sysu/go/network/QRApiService.kt`
  - Estimated effort: ~30 min

- [ ] **BUG-3: `registerTrip()` walang fallback — silent failure kapag offline ang Railway**
  - Unlike QR scan na may Firestore fallback, trip registration walang retry at walang fallback
  - Fix: Add Firestore direct-write fallback OR retry with exponential backoff
  - File: `app/src/main/java/com/sysu/go/network/TripApiService.kt`
  - Estimated effort: ~1-2 hrs

- [ ] **BUG-4: `driverId` field inconsistency — UID vs queue doc ID sa `sap_assignments`**
  - Some code paths write Firebase UID, some write queue doc ID as `driverId`
  - This breaks `DriverShipmentSync` (never finds assignments) → Fleet Manager sa sysu-app sees driver as unassigned
  - Fix: Confirm `sapAssignmentController.js` (backend) consistently writes Firebase UID
  - Files: `backend/src/controllers/sapAssignmentController.js` + `app/.../AssignmentActivity.kt`
  - Estimated effort: ~30 min investigation + fix

## 🟡 HIGH PRIORITY — Before Wider Release

- [ ] **BUG-5: `clearSession()` hindi nag-cclear ng trip data**
  - Kapag nag-logout ang driver mid-trip tapos nag-login ulit (kahit ibang account), may stale na trip state
  - Fix: Call `clearTripSession()` inside `clearSession()`
  - File: `app/src/main/java/com/sysu/go/utils/SessionManager.kt`
  - Estimated effort: ~5 min

- [ ] **BUG-6: Duplicate Firestore instance sa `QueueDetailsActivity`**
  - `private val db` at `private val firestoreDb` — both are `FirebaseFirestore.getInstance()`, redundant
  - Fix: Remove `firestoreDb`, standardize lahat ng usage to `db`
  - File: `app/src/main/java/com/sysu/go/activities/QueueDetailsActivity.kt`
  - Estimated effort: ~10 min

- [ ] **BUG-7: GPS pin emoji (`📍`) possibly malformed sa POD image overlay**
  - Source uses literal emoji string na may encoding issues; may appear as `dY"?` sa ibang devices
  - Fix: Replace with Unicode escape `\uD83D\uDCCD`
  - File: `app/src/main/java/com/sysu/go/utils/ImageStorageHelper.kt`
  - Estimated effort: ~5 min

- [ ] **BUG-8: Release build hindi obfuscated (`isMinifyEnabled = false`)**
  - APK is larger, internal class names visible via reverse engineering, API URL exposed
  - Fix: Set `isMinifyEnabled = true` + `shrinkResources = true` for release, configure ProGuard rules
  - File: `app/build.gradle.kts`
  - Estimated effort: ~30 min (may need ProGuard rule tuning)

- [ ] **BUG-9: `pod_updated` socket event emitted by Android pero walang handler sa sysu-app dashboard**
  - `SocketManager.emitPodUpdated()` sends event pero `dashboard.js` walang listener — POD update requires manual refresh sa web
  - Fix: Add `socket.on("pod_updated", ...)` handler sa `dashboard.js` na mag-re-render ng affected shipment row
  - File: `frontend/src/pages/dashboard.js` (sysu-app repo)
  - Estimated effort: ~30 min

- [ ] **BUG-10: Firebase ID token hindi nire-refresh bago mag-API call**
  - Token expires after 1 hour; kung expired na, `TripApiService` at `QRApiService` will get silent 401 errors
  - Fix: Call `user.getIdToken(true)` (force refresh) before each API call, or use token expiry check
  - Files: `TripApiService.kt`, `QRApiService.kt`
  - Estimated effort: ~1 hr

- [ ] **No Espresso UI tests**
