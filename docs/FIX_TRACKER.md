## Ongoing review and update policy

This file is the canonical current status for SYSU-GO release findings. [RELEASE_TEST_PLAN.md](RELEASE_TEST_PLAN.md) owns planned validation; [RELEASE_FIXES_TDD.md](RELEASE_FIXES_TDD.md) owns executed RED/GREEN evidence and significant decisions; [LOCAL_EMULATOR_SETUP.md](LOCAL_EMULATOR_SETUP.md) owns environment setup. Historical assessment/TODO files are discovery input, not proof of completion. No automatic update hook is configured; the tracker is updated explicitly during each review/fix/testing batch.

- Add each newly verified finding immediately with the next unused G-ID, severity, affected file(s), priority phase, concrete impact/reproducer, and explicit done-when condition. Next unused ID is G-31; do not reuse IDs.
- Extend an existing finding when the same root cause is involved; add a separate ID when the cause or acceptance condition differs. Record unverified suspicions as pending investigation, not confirmed bugs or passing checks.
- OPEN means no verified fix yet. IN PROGRESS includes implemented local fixes with incomplete acceptance. DONE requires every stated acceptance condition to pass; passing local tests alone cannot close a finding requiring device, staging, deployment or IAM evidence.
- For each fix, record the test target, observed RED, observed GREEN, regression review, source-specific coverage where meaningful, checkpoint commit and remaining acceptance in the evidence report; link it from the tracker. Reopen the same ID if a regression invalidates its acceptance.
- Keep local implementation progress separate from release acceptance. Preserve completed work in the progress table below even while its parent finding remains IN PROGRESS. Recalculate totals after adding/reopening/closing findings; count repeated variants/reruns once when reporting distinct test cases.
- Update this tracker and the affected test/evidence document in the same batch. Record environment, artifact/commit and untested limits; include no credentials or private payloads. Recheck current code/results before carrying old claims into a new session.
