# Truck Company Dropdown — Firestore-Backed Design

**Date:** 2026-06-08
**Status:** Approved

---

## Overview

Move the hardcoded `truck_companies` string array out of `arrays.xml` and store the list in Firestore under a `truck_company` collection. The registration dropdown pulls from a local cache instead of a static resource file, enabling non-developer management of the company list.

---

## Data Structure

```
Firestore collection: truck_company
 Document ID: auto-generated by Firestore (no meaningful ID needed)

 Fields:
   name      string    — full company display name, e.g. "LALAMOVE PHILIPPINES INC"
   active    boolean   — true = appears in dropdown; false = hidden (soft-delete)
   createdAt timestamp — when the company was added

Security rules (Firestore):
  allow read: if true;   // drivers read only
  allow write: if <admin_condition>;  // only admin can add/update
```

All existing company names from `arrays.xml` will be seeded into Firestore as new documents with `active: true` and no changes to the `users` schema.

---

## Android Architecture

```
com.sysu.go.repository.TruckCompanyRepository
  getCached(): List<String>          — returns companies from SharedPreferences cache
  fetchFromFirestore(): List<String>  — network call, returns List of active names
  fetchAndCache(): Unit               — fetch + serialize to SharedPreferences JSON
  fetchOnStart(): Unit                — called by SplashActivity on warm start

com.sysu.go.activities.RegistrationActivity
  setupTruckCompanyDropdown()
    → reads from TruckCompanyRepository.getCached()
    → populates AutoCompleteTextView adapter
    → NO network call in this screen (data is pre-loaded)
```

**Local cache:** SharedPreferences under key `PREF_TRUCK_COMPANIES` as a JSON array of strings.

**Cache population:** `fetchAndCache()` is called from `SplashActivity` on every app open via `MainActivity` (since SplashActivity already routes through MainActivity). A synchronous local read is used on the registration screen — no loading spinner needed for the dropdown.

---

## Offline Behavior

- If Firestore is unreachable during `fetchAndCache()`, the existing SharedPreferences cache is left intact.
- If Firestore is unreachable AND the cache is empty (first launch with no data), an empty list is returned and the dropdown shows no options. Driver cannot proceed without a cached list — acceptable because this is a first-run setup scenario where a network call is expected to succeed at least once.
- A loading/empty state is not required for the dropdown itself (registration won't open without network on first use).

---

## Changes by File

| File | Change |
|---|---|
| `arrays.xml` | Remove all `<item>` entries from `truck_companies`. Keep the array key (avoids breaking references). |
| `TruckCompanyRepository.kt` | New class. `getCached()`, `fetchAndCache()`, `fetchFromFirestore()`. |
| `SplashActivity.kt` | Call `TruckCompanyRepository().fetchAndCache()` on app open. |
| `RegistrationActivity.setupTruckCompanyDropdown()` | Replace `resources.getStringArray(R.array.truck_companies)` with `TruckCompanyRepository().getCached()`. Remove `arrays.xml` dependency. |
| `MainActivity.kt` | No changes. |

No changes to the `users` Firestore schema. `truckingCompany` continues to store only the name string.

---

## Seed Data (Firestore)

All 46 companies from `arrays.xml` will be written as individual documents to the `truck_company` collection with `active: true`. No forwarder codes stored.
